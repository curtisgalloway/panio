# M5 evidence — control-host verification (release still pending)

Plan: [implementation plan](../implementation-plan.md). Design: [design](../design.md).
Build under test: `5e9505a` (M4 checkpoint), `cli/` built as a debug binary on
the control host (arm64 Linux) in a scratch directory and run by path. The
host's installed panio (0.4.1) and its running daemons were not touched. The
host's own lab file was used.

## R6 — the silent `power-cycle`

The consumer recorded, for 0.4.1 on this control host, "power-cycle of an
unknown target: rc 1 and no output at all". It did **not** reproduce with 0.4.1
on 2026-09-25 by any path the consumer uses:

| How 0.4.1 was run | rc | stdout | stderr |
|---|---|---|---|
| on the host, shell | 1 | empty | `target 'nosuch' not found in lab` |
| on the host, the consumer's exact call: Python `subprocess.run(["panio", "power-cycle", "nosuch"], capture_output=True, text=True)` | 1 | `''` | `"target 'nosuch' not found in lab\n"` |
| non-interactive `ssh <host> panio power-cycle nosuch` | 1 | empty | the same line |

With this build the same command prints the error and exits 3 (below), which
is R6's acceptance criterion. The earlier silence stays unexplained; since
neither version is silent on any path tried, R6 is closed as satisfied, with
this note so a recurrence is recognized.

## The consumer's cases, this build, `PANIO_JSON_ERRORS=1`

Chosen so no command can move hardware: each target lacks the channel asked
for, and the stopped-daemon case is a read-only `serial log`.

| Command | rc | stderr (message line, then the JSON object) |
|---|---|---|
| `power-cycle nosuch` | 3 | `target 'nosuch' not found in lab` / `{"error":{"channel":null,"child_exit":null,"code":3,"host":null,"kind":"not_configured","message":"target 'nosuch' not found in lab","target":"nosuch"}}` |
| `hid send -t target-a ping` (no hid channel) | 3 | `target 'target-a' has no hid channel (panio hid set -t target-a --cmd ...)` / `kind not_configured, channel "hid", target "target-a"` |
| `power-cycle target-b` (no power channel) | 3 | `target 'target-b' has no power channel (panio power set -t target-b ...)` / `kind not_configured, channel "power", target "target-b"` |
| `serial log target-c -i console` (no such interface) | 3 | `target 'target-c' has no serial interface 'console' (have: none)` / `kind not_configured, channel "serial", target "target-c"` |
| `serial log target-d --require-live` (serialcap stopped) | 100 | `serialcap daemon for 'target-d' is not running — the log shows nothing captured since it stopped (start it with `panio serial watch`)` / `kind daemon_down, channel "serial", target "target-d"` |
| `serial log target-d --tail 1` (serialcap stopped) | 0 | `warning: serialcap daemon for 'target-d' is not running — …`; no JSON object (not a failure) |

Every failing case printed exactly one JSON object, as the last stderr line,
with stdout empty. (Target names are replaced with `target-a`…`target-d`; the lab's real
names are machine names and stay out of this public repo.)

## Windows CI (first run of the branch, PR #242)

The `windows` job failed two integration tests that had only ever run on
Unix: both hook tests fed POSIX `sh` to hooks that Windows runs through
`cmd.exe /C`.

- `hooks_do_not_inherit_the_json_request`: the test's hook was `sh` syntax;
  it now uses `if defined PANIO_JSON_ERRORS (exit 9) else (exit 7)` on
  Windows, so the no-inheritance guarantee is checked there too.
- `a_missing_power_hook_is_not_configured`: a real gap. `cmd.exe` exits 1 for
  a missing script path, so panio reported 101, not the documented 3. First
  attempt (user decision): map `cmd.exe`'s 9009 to `not_configured`. The next
  Windows run disproved it: `cmd.exe /C` exits **1** for an unknown command
  too (log: `'panio-no-such-relay-command' is not recognized …` then
  `exited with code 1`); 9009 is only `%ERRORLEVEL%` inside a batch file.
  Final (user decision, 2026-09-25): no mapping; the 127 test is gated to
  Unix, and the Windows-only test `a_missing_hook_is_helper_failed_on_windows`
  pins the real behavior (101, `child_exit` 1), documented in
  `docs/errors.md` and the design.

Linux: clippy clean, 222 + 25 tests pass. The Windows paths are verified only
by the next `windows` CI run.
