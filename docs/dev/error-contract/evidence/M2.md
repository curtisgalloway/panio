# M2 evidence — the child boundary

Plan: [implementation plan](../implementation-plan.md). Design: [design](../design.md).
Starting revision: `652c785` (M1 checkpoint); branch `error-contract`.

## Milestone as planned

**Outcome:** a failing hook exits 101 with its code in `child_exit`; a
missing hook exits 3; a dispatch whose ssh exits 255 exits 4 with `host`
set; a remote failure arrives with its own code and exactly one JSON object;
a passthrough child killed by a signal exits 128+N, never 255.
**Design coverage:** R1 (unreachable, helper_failed), R3, R4.

**What changed**

- `error.rs`: `shell_code` (code, or 128+N for a signal), `hook_failed`
  (126/127 → `not_configured`, else `helper_failed`, `child_exit` = the code
  or null for a signal), `helper_missing`, `unreachable_host`,
  `SSH_TRANSPORT_FAILURE`.
- `ssh.rs`, `adb.rs`, `video.rs`, `serial.rs`: every `code().unwrap_or(-1|1)`
  is `shell_code`, so a signal-killed child is 128+N, never 255.
- Hooks → `hook_failed`: power `cycle/on/off_cmd`, `state_cmd`, `usb` helper,
  `hid send`, `hid stop`, `serialcap log`, `serialcap stop`, `hdmicap stop`.
- Dispatch: `ship_slice` classifies the SFTP copy (missing sftp → 3, other
  failure → 4 with `host`); ssh 255 → 4 in `dispatch`, `run_subcommand`,
  `dispatch_stdout_to_file`, `setup --host` and remote `adb devices`; the
  slice is removed before the 255 check.
- Passthroughs (design D3) keep the child's code: `config edit`, `helper`,
  `video` and `adb` passthroughs. A missing editor, bundled helper
  (serialcap, hdmicap, netbootd, tio) or adb binary is `not_configured`.
- `daemons stop` / `daemons restart` failures exit 109 instead of 1.
- Docs contradicted by the change fixed now: `docs/power.md` (power-cycle
  exit status) and `docs/dev/adding-power-helpers.md` (hook contract).
