# M1 evidence — error type and the `main()` mapping

Plan: [implementation plan](../implementation-plan.md). Design: [design](../design.md).
Starting revision: `65e38ea` (plan commit); branch `error-contract`.

## Milestone as planned

**Outcome:** `panio --lab lab.toml power-cycle nosuch` exits **3**; with
`PANIO_JSON_ERRORS=1` or `--json-errors`, the last stderr line is the JSON
error object. Unclassified errors exit **109**. Clap errors exit 2. `doctor`
still exits 1 for problems found.
**Design coverage:** R1 (usage, not_configured, internal), R2, R6 (local), R7.

**Acceptance criteria and result**

| Criterion | Result |
|---|---|
| Unknown target → 3, JSON `target` set | pass (`unknown_target_is_not_configured`: `power-cycle`, `serial log`) |
| Target without a channel → 3, JSON `channel` set | pass (`missing_channel_is_not_configured`: hid, power) |
| Unknown serial interface → 3 | pass (`missing_serial_interface_is_not_configured`, `unknown_dtr_interface_is_not_configured`) |
| Missing lab file → 3 | pass (`missing_lab_file_is_not_configured`) |
| Ambiguous target / interface host → 2 `usage` | pass (`ambiguous_target_is_usage`, `serial_on_two_hosts_without_an_interface_is_usage`) |
| Clap errors → 2, JSON when requested, none for `--help` | pass (`clap_usage_errors_exit_2_with_a_usage_object`) |
| Unclassified → 109 `internal` | pass (`unclassified_error_is_internal`; M3 moves this example to 100) |
| Without opt-in, stderr is exactly the 0.4 text; flag ≡ variable; stdout clean | pass (`no_json_unless_requested_and_the_flag_matches_the_variable`) |
| `--json-errors` crosses dispatch when requested; a repeat is accepted | pass (unit `dispatch::tests::json_errors_crosses_the_hop_when_requested`, `a_repeated_json_errors_flag_is_accepted`) |
| `doctor` still exits 1 | unchanged code path (`cmd_doctor`), not re-tested |
| R6 silent power-cycle | **not reproduced locally** with 0.4.1 or this build (prints and exits 3); the control-host repro is M4 |

Known limit, not fixed: on a *parse failure*, `report_parse_error` decides
whether JSON was requested by scanning raw argv for `--json-errors` before
`--`, so a payload token of that spelling on a command that already failed to
parse can add the usage object. Harmless (the exit code is 2 either way) and
unavoidable without a successful parse.
