# M3 evidence — daemons, timeouts, `serial log`

Plan: [implementation plan](../implementation-plan.md). Design: [design](../design.md).
Starting revision: `ddd8189` (M2 checkpoint); branch `error-contract`.

## Inventory (the milestone's first step)

`rg` over `cli/src` for daemon-down, timeout and device-node sites:

| Kind | Sites |
|---|---|
| daemon_down (100) | `serial send`, `power-state` sense (serialcap); `console`, `video preview`, OCR (hdmicap) — each a `daemon(&target)` lookup that found no discovery record. Plus any daemon request refused at connect (a stale record). |
| timeout (22) | `daemons::start_failure` (4 start paths: restart, `serial watch`, `video watch`, `console`, hid serve), `ssh::forward` port wait, a daemon request that timed out. |
| helper_failed (101) | a daemon answering an error status (`/input`, `/button`, OCR, stable-frame wait); a daemon that exited during startup. |
| device node (4) | **none**: panio never opens or stats a device node before a daemon does; the daemons report it, through start failure or an error status. Design table row 4 and the plan's M3 outcome revised. |

hid and netbootd: hid is started on demand (`hid serve`, `console`), so only its
start failure applies; netbootd has its own `netboot status` reporting and no
"needs the daemon" command path.

### Re-review of the fixes

Method: one fresh-context reviewer subagent, given the refereed findings,
both diffs and the user's decisions; quote-backed verdicts. All ten findings
**fixed**. Regression checks it reported clean: holding the spawned `Child`
changes nothing about daemon lifetime (std's `Child` neither kills nor waits
on drop; detach is unchanged; no piped stdio); the
`ConnectionFailed | Io if is_timeout(t)` arm matches ureq 2.12.1 (connect
errors are `ConnectionFailed` wrapping the io error; a connect deadline is
`TimedOut`; a read timeout's `WouldBlock` becomes `TimedOut`); `with_target`
keeps an already-set target; the F9 check costs one `ps` scan, only when the
discovery file is missing.
