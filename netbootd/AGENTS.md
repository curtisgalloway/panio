# netbootd/ — agent notes

This file holds the internals of netbootd/, moved out of the root AGENTS.md to keep it short. The root AGENTS.md rules still apply here; per-OS behavior lives in [docs/dev/platform-support.md](../docs/dev/platform-support.md).

## netbootd (Rust netboot engine)

`netbootd/` is a single-binary DHCP + read-only TFTP + HTTP server, all as tokio tasks in one process. It is the **only** netboot engine for `paniolo netboot start`.

Tests: protocol logic is unit-tested in `dhcp.rs` / `tftp.rs` / `http.rs` `#[cfg(test)]` modules. A 65K-round-trip block-wraparound test is `#[ignore]`; run it with `cargo test -- --ignored`. `dhcp::serve` is deliberately not driven end-to-end: it shells out to `sudo arp`/`ip neigh` on every accepted request, which a test must never trigger. `disposition` (the whole per-packet decision, including the order the message type and client lock are settled in) and `accept_client` carry that coverage. `tftp::run` has no shell-out and is driven over loopback for the peer-IP gate and the `MAX_TRANSFERS` bound ("Peer gating" and "Transfer-slot bound" groups in `tftp.rs`).

Startup order is fixed: validate → bind and pin every listener → drop root (Linux) → serve. Each server exposes `bind_server(port, interface)` (sync, called from `main` before anything runs concurrently; `interface` is a `pin::ListenerInterface` holding the macOS lock) and `serve(socket, …)`.

- **In-process MAC handoff.** The DHCP task publishes the client's hardware address to the TFTP task via `tokio::sync::watch`; there is no on-disk `client-mac` file.
- **Every listener is pinned to the netboot interface** (`src/pin.rs`: `IP_BOUND_IF` on macOS, `SO_BINDTODEVICE` on Linux) before it is bound. A failed pin is fatal, as is a DHCP or TFTP bind failure; `--interface` is required. Only the HTTP bind is non-fatal: a port clash logs a warning and netbootd runs DHCP + TFTP without HTTP Boot. `main.rs` reads the actual bound port back (`local_addr()`, correct for `--http-port 0`) and hands DHCP an `Option<u16>` (`None` = no listener). `dhcp::serve`'s `choose_boot` never builds an `http://` URL without a real bound port: an `HTTPClient` DISCOVER/REQUEST with no HTTP endpoint is ignored with a rate-limited warning, not answered with a URL to nothing (#144).
  - UDP listeners carry no `SO_REUSEADDR` (UDP has no TIME_WAIT, and on Linux it would let a duplicate daemon share the port); the TCP listener keeps it for TIME_WAIT. macOS listeners also use `SO_REUSEPORT` so separate pinned interfaces can share the standard ports (#204).
  - `pin::ListenerInterface` holds a system-wide, per-interface `flock` from before any bind until daemon exit, so a duplicate direct launch fails too. The lock file stays in `/tmp`; never unlink a live lock.
- **Root is dropped on Linux** (`src/privdrop.rs`) right after the listeners are bound: `setgroups(empty)` → `setgid` → `setuid` to `SUDO_UID`/`SUDO_GID`. Any failure is fatal, and the drop is verified irreversible (`setuid(0)` must fail). The decision is the pure, unit-tested `drop_target`; the syscalls need root and are untested. Later `sudo ip neigh` / `sudo ip addr` shell-outs run as the dropped user, hence passwordless sudo on Linux. macOS is never privileged. Every shell-out while serving goes through `tokio::process` so none blocks a runtime worker.
- **One lease, derived from the host IP** (`dhcp::derive_client_ip`: the host's /24, last octet 100, or 101 when the host is .100; `--client-ip` overrides, `validate_client_ip` refuses anything outside the /24). A REQUEST for another address is NAKed (`request_verdict`), one addressed to another server (option 54) is ignored, and non-Ethernet / `hlen != 6` clients are dropped.
- **One client, enforced by MAC** (`dhcp::accept_client`, sequenced by `dhcp::disposition`). The first DISCOVER, or first REQUEST this server actually answers, locks that hardware address as the active client for the process's lifetime. A later request from a different MAC is ignored outright (no OFFER/ACK/NAK; a `warn!` rate-limited via `served::warn_rate_limited`), so a second device cannot steal the lease, the ARP pin, or the MAC handed to TFTP's raw-frame sender. A retransmission from the active MAC is unaffected (`accept_client` is idempotent for it).
  - The message type is settled BEFORE the lock is touched: a DHCPINFORM/DECLINE/RELEASE, or a REQUEST addressed to another server (option 54), takes no lock whoever sends it, so an unrelated host cannot lock out the real target with a packet netbootd would never answer (#166). A NAKed REQUEST does take the lock, since a NAK is a reply.
  - There is no lease timer and no in-process reset: `paniolo netboot start`/`stop` restarts the process per boot session, so a new client means restarting netbootd.
- **TFTP is gated to the leased client and bounded in concurrency** (`tftp::run`). Every RRQ/WRQ whose source IP is not the one DHCP leases on this link (`client_ip`, threaded from `main` into `tftp::serve`) is dropped silently. Transfers are capped by a `MAX_TRANSFERS`-permit (currently 4) `tokio::sync::Semaphore`: the permit is taken with `try_acquire_owned` before the transfer task is spawned and moved into it, so it is released whenever the task stops (completion, read/send error, or `abort()` when a repeated RRQ from the same TID replaces it) with no other bookkeeping. An RRQ that finds every slot taken is dropped, not queued (TFTP has no "try again shortly"), so a flood of unique-source RRQs cannot grow tasks, sockets or open files without bound. A rate-limited `warn!` covers a sustained flood of either rejection.
- **Hardened against the far end of the link.**
  - TFTP streams blocks from the file (`seek` + bounded read; nothing is read whole), gives each retransmit attempt a fixed `Instant` deadline (junk cannot re-arm it), replaces an in-flight transfer on a repeated RRQ from the same TID (`abort` the old task), and caps `blksize` at 1468 when replies go out as raw frames (`cap_blksize`). `frame::build_udp_frame` refuses a payload the 16-bit length fields cannot describe.
  - HTTP: 10 s head/body-drain timeout, 64 concurrent connections (`Semaphore`), HTTP/1.0 defaults to close, and a body is exactly the announced `Content-Length` (grown file → cut; shrunk file → connection dropped).
  - Peer-supplied names go through `served::loggable` (printable ASCII, capped) before reaching the log. SIGTERM shuts down cleanly like Ctrl-C.
- **Privilege-separated `/dev/bpf` on macOS.** The raw-frame send path (the Sequoia workaround) needs a BPF descriptor only root can open, so netbootd stays **unprivileged** and a tiny **setuid-root** helper, `netbootd-bpf-helper`, does the open. It opens `/dev/bpfN` **write-only**, binds it (`BIOCSETIF`), sets `BIOCSHDRCMPLT`, installs a reject-all filter (`BIOCSETF`, `ret #0`), passes the fd back over a `socketpair` via `SCM_RIGHTS` (`src/handoff.rs`), then exits. netbootd only `write(2)`s frames to the fd (`src/bpf.rs::BpfSender::from_handoff`). The fd cannot capture (no `FREAD`, so `read(2)` fails, and the filter accepts nothing) and is `FD_CLOEXEC` so the daemon's `sudo arp`/`ifconfig` children never inherit it.
  - The helper is the only component that runs as root. `paniolo setup` installs it setuid 4755 (the one-time sudo) and refuses to setuid a symlink or a file the invoking user does not own. The helper also gates itself rather than trusting the mode: it refuses any caller whose real uid is not the owner of its directory (`handoff::caller_allowed`: the installing user, or root) and refuses the default-route interface (`handoff::interface_refused`, via `route::default_route_interface`, which runs `/sbin/route` by absolute path with an empty environment).
  - If the helper is missing, not setuid, or refuses, netbootd logs its exit status and stderr and falls back to the kernel `send_to` path (broken on macOS 15+).
- **Linux and Windows have no BPF path**: netbootd uses the kernel `send_to` (with retry). The BPF sender, helper and fd handoff are macOS-only.
- **Primary-NIC guard.** `netcfg::is_primary_interface` makes `main()` refuse to start, and `monitor_interface` refuse to enforce, on the default-route interface.
- **Layout.** `src/lib.rs` exposes `frame` (frame builder), `handoff` (BPF open, fd passing, the helper's caller/interface policy) and, on macOS, `route` (default-route lookup), shared by the `netbootd` and `netbootd-bpf-helper` binaries; all three are unit-tested. Daemon-only modules: `dhcp`, `tftp`, `http`, `served` (shared path resolution + log sanitizer), `pin` (interface pinning), `privdrop` (Linux root drop), `netcfg` (ARP pin + IP monitor shell-outs), `bpf`.
- **`paniolo netboot start` checks liveness.** After spawning, the CLI watches the child for ~2 s (`try_wait` + the named-process probe) and only then writes the state file; an early exit fails `start` with the last 20 log lines. It refuses a second target on an interface another target's live netbootd already serves (`state::running_netboots`; one netboot per interface). Subnets are one per link: `netif::configure_interface` refuses a /24 any other interface on the host already holds (the live side), `netboot set` refuses `model::netboot_subnet_clash` for the link being edited, and `doctor` reports it as `CONFLICT`. `target show` always prints the netboot host IP, `(default)` when unset.
